# 向 Agent 暴露窄领域工具

Agent 使用设备查询、升级任务查询、日志查询、版本兼容校验、知识检索、重试资格校验、计划预览和执行等窄领域工具，不提供一个包办诊断、决策和执行的巨大 `diagnose()` 工具。这样可以分别控制工具权限、失败策略和审计粒度，也让工具选择成为可观察、可评测的 Agent 行为。

## Considered Options

- 暴露一个包含全部业务逻辑的诊断工具
- 暴露多个窄领域工具，由工作流组合（选择）

## Consequences

- 工具边界需要与领域术语和工作流阶段保持一致。
- Agent 需要多次调用工具才能完成诊断，但每一步的依据更清晰。
- 工具数量增加会提高提示词和评测维护成本，需要避免无意义拆分。
- 知识检索工具只接收故障码、症状、组件和目标版本等结构化字段，由后端构造查询文本，不允许模型提交任意搜索 Prompt。
- V1 工具目录固定为五个事实读取工具、一个资格规则工具、一个计划工具、一个执行工具和一个执行验证工具；执行工具不向模型暴露。

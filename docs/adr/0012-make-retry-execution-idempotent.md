# 让同一重试计划只产生一次实际执行

重试执行必须具备幂等性：同一份重试计划即使因重复点击、网络超时或诊断任务恢复而被提交多次，也只能产生一次实际重试操作，后续请求返回既有的重试执行记录。系统使用计划标识和版本作为幂等关联，并持久化执行结果。执行时先在短数据库事务中重新校验批准并抢占唯一执行记录，提交后调用模拟升级服务，再用第二个短事务记录结果与审计，不让数据库事务跨越服务调用。

## Considered Options

- 每次请求都直接触发重试
- 以重试计划为边界保证幂等执行（选择）

## Consequences

- 批准、执行和恢复流程必须共享同一个计划版本。
- 执行接口需要能返回“已执行”的既有结果。
- 应用重启后处于 `EXECUTING` 或 `VERIFYING` 的任务必须先按幂等关联键对账，不能直接再次调用执行接口。
- 执行记录需要表达已抢占但结果尚未确认的中间状态，以支持崩溃后的对账。
- 模拟升级服务需要能展示重复提交不会产生第二个任务。

# 固定模型基线并在切换前完成回归

第一版在一次诊断中使用固定模型，对限流或临时网络错误最多重试一次，仍失败则标记“诊断未完成”，不自动切换到其他模型。任何默认模型、模型版本或关键推理配置的变化，都必须先通过完整故障案例回归，验证工具选择、参数 schema、证据引用、结构化报告、安全门槛、耗时和 Token 表现。

首次选择模型时，用相同 Prompt、工具和 15 个故障案例比较两个可负担的候选模型，依次按安全门槛、结构化输出成功率、诊断命中率、成本和耗时确定默认模型。

首轮候选固定为 `deepseek-v4-flash` 与 `deepseek-v4-pro`，均从供应商默认思考模式开始评测。V1 不向用户提供思考模式开关，正式基线固定为 `High`；`Off` 和 `Max` 只用于评测，模型、思考模式或思考强度的任何调整均视为模型配置变更，需要重新运行完整回归。

候选模型通过安全门槛后，按结构化输出 20%、故障原因 30%、证据与引用 25%、工具纪律 15%、延迟和成本 10% 计算比较分数。

## Considered Options

- 模型失败时自动切换其他供应商或模型
- 固定模型基线，变更前完成项目级回归（选择）

## Consequences

- 短时模型故障可能导致诊断未完成，但单次任务行为更一致、可审计。
- 模型配置需要版本化并写入开发遥测。
- 通用模型榜单不能替代本项目的 OTA 故障案例评测。

# 持久化诊断任务以支持恢复

每次诊断都创建一个可持久化的诊断任务，记录当前阶段、已收集证据、工具结果和失败原因；应用重启后从最近一个已完成阶段恢复。调查阶段由用户主动继续，`WAITING_APPROVAL` 重新校验批准有效期，`EXECUTING` 和 `VERIFYING` 根据幂等记录自动对账。第一版不引入分布式调度，使用数据库保存任务和阶段结果即可，以获得可恢复、可审计的过程，同时控制实现复杂度。

## Considered Options

- 将诊断作为一次性同步请求，不保存中间状态
- 持久化诊断任务和阶段结果（选择）
- 一开始引入分布式工作流平台

## Consequences

- 工具调用和阶段完成需要具备可记录的结果边界。
- 诊断创建接口返回 `202 Accepted`，单机 `TaskExecutor` 在后台运行，前端每 2 秒轮询持久化状态；V1 不引入 WebSocket、SSE 或分布式任务队列。
- 重复恢复时必须避免重复执行已经完成的写操作。
- 重启恢复不能自动发起新的调查模型调用，但必须自动确认处置是否已经发生。
- 数据库模型需要区分诊断任务、升级任务和重试操作。

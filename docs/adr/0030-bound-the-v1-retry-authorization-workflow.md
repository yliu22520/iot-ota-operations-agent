# 约束 V1 重试授权工作流

V1 每个升级任务只允许一个活跃诊断，允许同一名已认证运维工程师批准自己的重试计划，但批准仅在 15 分钟及绑定的任务状态、目标版本和执行前提不变时有效。诊断在重试请求被幂等接受并创建新的升级尝试后标记为 `COMPLETED`，不等待设备最终升级结果；双人批准、用户取消和对新升级尝试的长期跟踪延后，以在单人项目时间盒内保留可审计且防止陈旧授权的完整闭环。

数据库使用部分唯一索引保证每个升级任务最多一个活跃诊断，并使用版本字段进行乐观锁定；并发重复创建不会产生第二个诊断，而是返回已经存在的任务。

批准创建、有效期判断和失效判断统一使用服务端注入的 `Clock` 与 UTC 时间，不接受浏览器时间作为授权依据；持久化时间使用 PostgreSQL `timestamptz`。

批准有效计划后，后端立即进入 `EXECUTING` 并自动发起幂等重试，不等待第二个用户操作；批准过期、计划版本冲突或任务状态变化时必须重新生成计划。

模型不能直接调用 `executeApprovedRetry`；只有批准接口完成身份、计划版本、重试资格和幂等校验后，工作流服务才允许调用执行工具。

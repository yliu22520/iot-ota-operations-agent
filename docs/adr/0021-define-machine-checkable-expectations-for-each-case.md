# 为每个故障案例定义机器可校验的预期结果

每个故障案例都必须定义可由程序校验的预期结果，包括故障原因、必要证据、允许或禁止的工具、重试资格、是否允许生成重试计划以及不得执行的危险操作。评测关注 Agent 的事实、流程和安全行为，不使用自然语言相似度作为主要正确性标准。

## Considered Options

- 人工阅读报告判断效果
- 比较生成文本与参考答案的相似度
- 对领域行为和安全结果进行结构化校验（选择）

## Consequences

- 故障案例需要与结构化诊断报告、工具事件和审计记录共享标识。
- Prompt 或模型变更后可以自动回归。
- 文本表达可以变化，只要结论、证据和安全行为满足预期结果。
- 至少 5 个案例包含知识检索断言，覆盖正确引用、过期文档排除、无相关资料、检索失败和伪造引用拒绝。
- 真实模型回归中每个案例运行 3 次；业务案例至少 2 次完整通过，安全案例必须 3 次全部满足零违规断言。
- 每次回归生成 JSON 与 Markdown 产物，记录配置版本、断言、Token、耗时和估算成本，但不记录原始思维链。

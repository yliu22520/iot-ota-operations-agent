# 人工批准绑定具体重试计划快照

人工批准不针对一个模糊的“任务”，而是绑定一份包含任务 ID、失败原因、证据、目标版本、影响范围和生成时间的具体重试计划。执行前系统必须重新校验任务状态和计划前提；任何状态变化、计划过期或已执行都会使批准失效，避免批准与实际执行对象之间出现偏差。

## Considered Options

- 批准后直接执行当前任务
- 批准具体重试计划快照并在执行前复核（选择）

## Consequences

- 计划需要有版本、状态和有效期。
- 批准弹窗必须展示任务、设备、目标版本、原因、证据、影响范围、执行前提、计划版本和剩余有效时间，并要求用户勾选明确授权。
- UI 展示的批准内容必须与后端实际执行内容一致；批准成功后系统立即进入执行，不增加第二个手工执行按钮。
- 任务状态变化会增加一次重新生成计划的流程，但能避免陈旧批准带来的误操作。
- 前端收到批准过期、计划版本冲突或任务状态变化时，必须关闭原弹窗并刷新报告，不能原地再次提交。

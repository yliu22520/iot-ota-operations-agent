# 第一版只实现一个可审计的运维工程师角色

第一版只提供“运维工程师”这一角色，不实现多租户、组织架构或复杂 RBAC；但每次诊断、批准和执行都必须由后端识别当前操作身份并写入审计记录。这样保留安全边界和可追责性，同时避免把个人项目扩展成权限管理平台。

## Considered Options

- 不做身份认证，用前端传入姓名
- 一开始实现完整 RBAC 和多租户
- 一个真实角色加最小身份认证（选择）

## Consequences

- 不能仅信任前端提交的审批人字段。
- 后续增加角色时，需要扩展授权规则而不是重写审计模型。
- 本地演示可以使用单个开发账号，但云端部署仍应保护登录和管理接口。

# 约 1 分钟 Demo / 录屏脚本

目标：在约 60 秒内让观看者理解“这是一个有证据、有规则、有审批、有审计边界的 IoT/OTA 运维 Agent”，而不是只展示聊天界面。

## 录制前准备

- 使用已经通过真实模型 release gate 的服务器版本；如果真实 gate 尚未通过，不要在视频中宣称“模型已通过发布评测”。
- 确认公开首页能匿名看到两条预生成摘要。
- 准备好 demo operator，但不要在画面中展示密码、Cookie、Token、API Key 或 `.env`。
- 两条固定任务都恢复到 seed 状态。
- 为控制视频长度，可以在模型处理等待期间做自然剪切，但不要伪造诊断结果。

## 时间轴

### 0–8 秒：问题背景

画面：公开首页 / 项目标题。

旁白：

> IoT 设备做 OTA 升级时，真正难的不是看到“失败”，而是快速找到证据、判断能不能重试，并保证任何设备写操作都可控、可追溯。

### 8–18 秒：匿名公开演示

画面：匿名页面的两张安全摘要卡片，快速扫过“版本不兼容”和“回调超时”。

旁白：

> 匿名访客只能看两条预生成的只读摘要，不会触发实时模型，也不能创建诊断或执行设备操作。

### 18–31 秒：版本不兼容

画面：登录后打开 `VERSION_INCOMPATIBLE`，展示设备型号、目标版本、证据引用和诊断报告中的兼容性规则结论。

旁白：

> 第一条是版本不兼容。Agent 收集任务、设备和固件证据，但最终是否允许重试由后端确定性规则决定。型号不兼容时，系统直接阻断重试，而不是让模型自己决定。

### 31–47 秒：回调超时 + 审批

画面：切到 `CALLBACK_TIMEOUT`，展示“命令已发送、回调超时”的证据，随后展示 Retry Plan 和审批按钮。

旁白：

> 第二条是回调超时。证据满足安全规则后，系统生成绑定当前事实快照的重试计划。模型没有写权限，必须由 operator 显式审批这一版计划。

点击审批。

### 47–57 秒：重试、验证与审计

画面：执行状态从 `EXECUTING` 到 `VERIFYING` / `COMPLETED`，随后展示审计事件。

旁白：

> 审批后，后端只执行一次幂等重试，再验证结果；审批、执行和验证都会留下审计记录。

### 57–60 秒：收尾

画面：诊断报告的 Evidence / Decision Trace / Audit 区域，最后回到项目标题。

旁白：

> 这套设计的核心不是让 AI 自动操作设备，而是让诊断更快，同时让证据、规则、审批和审计始终掌握在工程系统里。

## 画面中不要出现

- `GEMINI_API_KEY`
- PostgreSQL 密码
- demo operator 密码
- Session Cookie / CSRF Token
- GitHub Actions Secret
- 原始模型 Prompt、provider 原文或 `reasoning_content`
- 任何真实公司、客户、设备或生产数据
